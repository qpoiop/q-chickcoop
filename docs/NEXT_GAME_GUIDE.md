# 다음 게임 개발 가이드 (덕코프 기준)

3D 트윈스틱 액션 로그라이트를 **처음부터 제대로** 만들기 위한 실전 가이드.
목표 수준 = **덕코프/Ascent 급 상용 게임**(AAA가 아니라, AAA도 당연히 쓰는 기본기가
전부 자연스럽게 굴러가는 "완성된 상용 3D 액션"). CHICKCOOP에서 실제로 삽질한 것들을
근거로 뽑았다. **이 문서의 핵심은 "뭘 먼저 갖추고, 뭘 절대 하지 말라"이다.**

---

## 0. CHICKCOOP 포스트모템 — 왜 헛짓이 됐나

솔직한 원인. 다음엔 이걸 반복하지 않는다.

1. **데코용 GLB 씬을 플레이 맵으로 썼다.** Sketchfab "city/forest" 씬은 감상용이지
   플레이 아레나가 아니다. 결과: 하버스트 콜리전이 사방을 막고, 언덕/나무가 카메라를
   가리고, 앵커가 지붕·허공에 박히고, walkable이 9~44%밖에 안 됨 → "이동 안 됨/가려짐".
   **→ 교훈: 플레이 공간은 플레이용으로 설계된 지오메트리여야 한다.**
2. **손 없는 캐릭터에 총을 쥐게 했다.** 병아리 모델엔 손·팔·무기 소켓이 없다. 총 GLB가
   옆구리에 떠있고, 사격 자세·리코일·머즐이 안 나온다. **값 튜닝으로 못 고침 — 에셋 문제.**
3. **모델 하나로 다 돌려막았다.** 플레이어=잡몹=보스가 전부 같은 병아리. 실루엣·역할·색
   구분이 없어 난전에서 뭐가 뭔지 모름.
4. **로직이 아니라 소수점을 만졌다.** "정중앙 스폰 대칭 아레나", "고정 코너 스폰" 같은
   구조 문제를 두고 `moveSpeed 10→10.2` 같은 값만 계속 바꿈. **증상이 아니라 구조를 고쳐라.**
5. **핸드롤 three.js로 엔진 기능을 맨손 재구현했다.** 지형추적·애니메이션 블렌딩·파티클·
   라이팅·카메라 오클루전 — 상용 엔진이 공짜로 주는 걸 전부 직접 짜다 반쪽만 됨.

**한 줄 요약: 에셋과 엔진이 기본기를 받쳐주지 않는 상태에서 코드로 우겨넣으려 해서 실패했다.**

---

## 1. 시작 전에 갖출 것 (에셋 우선, 코드는 나중)

콘텐츠·튜닝 들어가기 전에 **이게 먼저 확정**돼야 한다. 순서 지켜라.

- **① 리그드 캐릭터 + 무기 소켓.** 손/팔이 있고 애니메이션(idle/run/**fire**/hit/death)이
  들어간 캐릭터. 무기는 손 본(bone)에 붙는 소켓 기준. 이게 있어야 "총 든 사격"이 성립한다.
  → CHICKCOOP 사격 문제의 근본. **캐릭터가 총과 안 맞으면 사격형(드론/구체/마법)으로 컨셉을 바꿔라.**
- **② 통일된 맵 킷.** 같은 아트 스타일의 바닥/벽/장식/props 모듈. 감상용 단일 씬 말고
  **조립 가능한 타일/모듈**. 지형 높이(heightfield)를 쓸 거면 처음부터 설계.
- **③ 적 3~5종, 실루엣/색/역할이 다른 것.** 근접 돌격 / 원거리 / 포위 / 탱크 / 스플리터.
  플레이어와 명확히 구분되는 실루엣.
- **④ VFX/SFX 팩.** 머즐, 피격, 폭발, 픽업, 발소리, 무기별 사운드. juice의 재료.
- **⑤ 일관된 팔레트 + 라이팅 컨셉.** 3~5색 액센트, 그림자 방향, 앰비언트. 룩의 70%.

> **하지 말 것: 위 5개 없이 코드부터 짜기.** CHICKCOOP이 그래서 껍데기가 됐다.

## 2. 엔진/기술 선택

**핸드롤 three.js 재고.** "제대로" 만들 거면 상용 엔진이 기본기를 공짜로 준다:

| 필요 기능 | 상용 엔진(Unity/Godot/Unreal) | 핸드롤 three.js |
|---|---|---|
| 지형 + 지형추적 이동 | Terrain + NavMesh 내장 | 직접 heightfield + 레이캐스트 |
| 애니메이션 블렌딩/IK | Animator/AnimationTree | AnimationMixer 수동 |
| 물리/콜리전 | 내장 | 직접 AABB/슬라이드 |
| 파티클/VFX | VFX Graph/GPUParticles | 스프라이트 수동 |
| 라이팅/그림자/포스트 | 내장 파이프라인 | 수동 + 블룸 함정 |
| 카메라(추적/오클루전/셰이크) | Cinemachine 등 | 수동 |

- **웹 배포가 필수 아니면 → Unity 또는 Godot.** 위 기본기 전부 즉시 확보.
- **웹이 필수면 → three.js는 유지하되, 처음부터 시스템을 제대로**(아래 3~8절). 단 지형·
  애니메이션·파티클을 맨손 재구현하는 비용을 각오. CHICKCOOP은 이걸 과소평가했다.

## 3. 캐릭터 & 사격 (기본기 #1)

- 캐릭터는 **무기 소켓(손 본)** 필수. 무기는 소켓에 부착 → 자동으로 손에 들림.
- 사격 시퀀스: **fire 애니 재생 → 총구(barrel tip, 빈 트랜스폼)에서 머즐 VFX + 탄 + 라이트
  → 리코일(무기 뒤로 킥 + 살짝 pitch) → 카메라 킥.** 이 전부가 "총구 위치"에서 나와야 한다.
- 머즐 = 총구 소켓에 붙는 **빌보드 섬광**(소프트 방사형, 무기 색, ~0.06s). 평면에 흰색
  단색 = 깨진 사각형(CHICKCOOP 실수).
- 조준: 트윈스틱은 우스틱/마우스 방향. 몸통은 이동 방향(또는 aim) — **일관되게** 정하라.
- **탄이 나가는 지점 = 총구 = 머즐 = 라이트, 셋이 같은 트랜스폼.** CHICKCOOP은 이게 다 따로 놀았다.

---

## 4. 이동 & 지형 (기본기 #2)

- **지형추적:** 매 프레임 발밑 지형 높이 샘플(레이캐스트 또는 heightfield 조회) → 캐릭터 y를
  부드럽게 맞춤. 경사면은 법선 따라 살짝 기울임(선택). 적도 동일.
- **경사 vs 벽:** 완만한 경사 = 걸어서 오름. 가파른(임계각 초과) = 막힘. **각도로 판정.**
- **콜리전은 walkable 그리드 하나로 통일.** CHICKCOOP은 그리드 + 하버스트 박스가 이중으로
  싸워서 도로가 막혔다. **한 소스로.**
- 이동은 가속/감속 있는 관성 + 대시. 즉각성과 무게감 밸런스.
- **카메라는 지형 높이를 반영.** 캐릭터가 언덕 오르면 카메라도 따라 올라가고, 앞 지형이
  시야를 가리면 페이드/X-ray 또는 각도 보정.

---

## 5. 카메라 (기본기 #3)

- 탑다운/쿼터뷰: 각도·줌·리드(조준 방향으로 약간 당김)·부드러운 추적.
- **오클루전 처리 필수.** 캐릭터 앞 지오메트리는 페이드 아웃하거나 X-ray. 안 하면 "언덕에
  다 가려짐"(CHICKCOOP). → **애초에 큰 오클루더를 플레이 공간에 두지 않는 설계가 우선.**
- 히트/대시/보스등장에 셰이크·킥·짧은 줌. juice의 절반은 카메라.

---

## 6. 전투 juice (기본기 #4 — 손맛의 실체)

덕코프 "치는 맛"은 아래가 촘촘히 겹쳐서 난다. 하나라도 빠지면 밋밋:

- **히트스톱**(피격 순간 몇 프레임 정지), **넉백**, **피격 플래시**(적 흰색 번쩍),
- **파티클**(임팩트 스파크/피/먼지), **스크린셰이크**(약하게, 남발 금지),
- **스쿼시&스트레치**(발사·피격·대시에 캐릭터 변형), **데미지 넘버**,
- **사운드 레이어링**(발사+임팩트+저역 펀치), **무기별 다른 손맛**(단순 수치 말고 리듬/반동/사거리).

> CHICKCOOP은 "쏘면 나가고 맞으면 죽음"뿐. 무기 5종이 수치만 다르고 손맛이 같았다.

---

## 7. 적 설계 (기본기 #5)

- **실루엣/색/모션으로 즉시 구분.** 플레이어와, 적끼리, 티어끼리 다 달라야 함.
- 역할 분담: 돌격/원거리/포위/방패/자폭 등 — 조합으로 상황이 만들어진다.
- **텔레그래프**: 근접·보스 공격 전 바닥 인디케이터 + 게이지 → "보고 피하는" 컨트롤.
- 스폰 디렉터: **플레이어 기준 링 스폰**(진행 따라옴) + 즉시 aggro. 고정 코너 스폰은 지나치면
  안 싸움(CHICKCOOP 초기 실수). 웨이브 리듬(러시↔숨틈).

---

## 8. 레벨/배치 (기본기 #6)

- **플레이 공간은 플레이용 지오메트리.** 데코 씬 금지. 방향성(끝에서 진입→전진→출구) 또는
  아레나(입장→클리어) 등 **의도된 흐름**.
- **모든 앵커는 실제 지면 위 + 도달 가능** 자동 검증(로드 시 레이캐스트 + BFS). CHICKCOOP은
  지붕·허공 박힘을 매번 손으로 잡았다 → 자동화.
- 목표는 스폰에서 **멀리** 둬서 횡단+전투 강제. "바로 앞 거 해킹하고 끝" 금지.
- 밝기/가독성 객관 측정(평균 휘도), 어두운 외곽에 목표 두지 말 것.

---

## 9. 코어 루프 (재미의 근본)

- **"한 판 더" 훅**: 무작위성(맵/적/드롭) + 빌드 성장(무기/스킬 시너지) + 메타 진행.
- 매 판이 다르게 느껴지는 이유가 있어야 함. CHICKCOOP은 해킹→포탈→보스 매번 동일 = 얕음.
- 빌드 다양성: 무기×스킬 조합이 플레이스타일을 바꿔야(카이팅/근접/포탑 등).

---

## 10. 아키텍처 원칙 (좋았던 것 — 유지)

CHICKCOOP에서 이건 잘했다. 다음에도:

- **데이터 주도**: 값=`data/*`, 동작=`engine/*`. 밸런싱은 데이터 편집.
- **공유 지오/머티리얼 캐시**: FX/픽업/링은 캐시 재사용(누수·GC 방지).
- **로드 시 자동 검증**: 앵커 지면/도달성/휘도 자동 체크로 리그레션 방지.
- **문서화**: 함정·컨벤션·측정법을 문서로 남겨 재발 방지(이 파일처럼).

---

## 11. 안티패턴 (절대 금지)

1. 데코 GLB 씬을 플레이 맵으로.
2. 캐릭터에 안 맞는 무기(손 없는데 총) 억지로.
3. 모델 하나로 플레이어/적/보스 돌려막기.
4. 구조 문제를 소수점 튜닝으로 덮기.
5. 에셋·엔진 기본기 없이 코드부터.
6. juice(히트스톱/파티클/셰이크) 생략하고 "쏘면 나감"으로 끝.
7. walkable 소스 이중화(그리드+박스 충돌).
8. 밝기·배치·오클루전을 눈대중으로(측정·자동검증 안 함).

---

## 12. 만드는 순서 (권장)

1. 엔진 결정 → 리그드 캐릭터+무기 소켓 확보 → **사격 한 방이 제대로 나오는 것**부터.
2. 이동/지형/카메라(오클루전 포함) — 기본 이동감 완성.
3. 적 1종 + 전투 juice — **"치는 맛"이 나는지**가 관문. 여기서 재미 안 나면 콘텐츠 무의미.
4. 스폰 디렉터 + 텔레그래프 + 적 3종.
5. 레벨 1개(의도된 흐름) + 자동 배치검증.
6. 코어 루프(빌드/진행/무작위성).
7. 그다음에야 콘텐츠 확장 + 밸런싱.

> **관문은 3번(전투 손맛).** 여기서 재밌으면 나머지는 확장. CHICKCOOP은 1~3을 건너뛰고
> 5~7을 튜닝하다 껍데기가 됐다. **손맛부터.**
