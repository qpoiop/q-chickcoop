# 3D 액션 게임 개발 가이드 (AAA 지향 · 자족)

3D 트윈스틱/탑다운 액션 로그라이트를 **처음부터 AAA급 크래프트로** 만들기 위한 실전
레퍼런스. 이 문서는 **자족적**이다 — 이전 프로젝트를 몰라도 이것만으로 시작할 수 있다.
실패한 한 프로젝트의 회고(`POSTMORTEM.md`)에서 뽑은 교훈을 **해야 할 것 / 하지 말 것 /
조심할 것 / 권장사항**으로 정리했다.

> **목표 수준 = AAA.** "그냥 걷고 뛰고 쏘고"가 아니다. 모든 상호작용(발사·피격·이동·픽업·
> 처치)이 **반응·피드백·연출**을 갖고, 아트·손맛·코드 구조가 상용 최고 수준이어야 한다.
> 콘텐츠 "양"은 팀·예산 문제지만, **크래프트·아키텍처·손맛은 첫 커밋부터 AAA 기준**으로.

---

## 0. 대전제 (이걸 어기면 아래 다 무의미)

- **에셋·손맛이 퀄리티의 80%.** 코드는 그걸 받쳐줄 뿐. 에셋 없이 코드부터 = 껍데기.
- **성공 = "재밌나 / 좋아 보이나".** 빌드 통과·배포 성공·에러 0은 성공이 아니라 **전제조건**.
- **수직 슬라이스 먼저.** 한 캐릭터·한 적·한 무기·한 방을 **AAA 손맛까지** 완성한 뒤 확장.
  여기서 재미 안 나면 콘텐츠 만들지 마라.

---

## 1. 해야 할 것 (DO)

### 캐릭터 & 사격
- **리그드 캐릭터 + 무기 소켓(손 본).** 애니 세트: idle/run/**fire**/hit/death. 무기는 소켓 부착.
- **총구(barrel) 트랜스폼 하나에서 전부 나오게**: 머즐 VFX + 탄 + 라이트 + 리코일. 셋이 같은 지점.
- **fire 애니 + 리코일(무기 뒤로 킥 + pitch) + 카메라 킥** 동기.
- 캐릭터가 무기와 안 맞으면(손 없음 등) **발사형 컨셉**(드론/구체/마법)으로 바꿔라.

### 전투 손맛 (juice — 이게 재미의 실체)
- **히트스톱**(피격 몇 프레임 정지), **넉백**, **피격 플래시**(적 흰색 번쩍), **임팩트 파티클**,
  **스크린셰이크**(약하게), **스쿼시&스트레치**(발사/피격/대시), **데미지 넘버**,
  **사운드 레이어링**(발사+임팩트+저역 펀치).
- **무기마다 다른 손맛**(리듬/반동/사거리/탄 패턴) — 수치만 다른 건 금지.

### 이동 · 지형 · 카메라
- **지형추적**: 발밑 높이 샘플 → 캐릭터 y 부드럽게. 경사=걸어 오름 / 가파름=벽 (각도 판정).
- **콜리전 단일 소스**(그리드 또는 physics 하나로). 이중화 금지.
- 이동은 가속/감속 관성 + 대시. **카메라**: 추적 + 리드(조준쪽 당김) + **오클루전 페이드/X-ray**
  + 셰이크/줌. 카메라가 손맛의 절반.

### 적 · AI · 스폰
- **실루엣/색/모션으로 즉시 구분**(플레이어 vs 적 vs 티어). 역할 분담(돌격/원거리/포위/탱크/자폭).
- **텔레그래프**: 공격 전 바닥 인디케이터 + 게이지 → "보고 피하는" 컨트롤.
- **스폰 디렉터**: 플레이어 기준 스폰(진행 따라옴) + 즉시 aggro + 웨이브 리듬(러시↔숨틈) + 난이도 예산.

### 레벨 · 배치
- **플레이 공간은 플레이용 지오메트리**로 설계. 의도된 흐름(끝에서 진입→전진→출구, 또는 아레나).
- **모든 앵커 자동 검증**(로드 시 지면 위 + 도달 가능 BFS). 목표는 스폰에서 멀리(횡단+전투 강제).
- 밝기/가독성 객관 측정. 어두운 외곽에 목표 두지 말 것.

### 아트 · 렌더
- **고정 렌더 파이프라인**: 라이팅(키/필/앰비언트) → 그림자 → 톤매핑 → 포스트스택(bloom/vignette/
  color-grade). 룩의 70%가 여기서. **팔레트·라이팅 컨셉을 아트와 함께 고정.**

### 아키텍처 · UX (아래 4~5절 상세)
- **시스템 경계** · ECS식 엔티티 · 이벤트버스 · 상태머신 · **시드 RNG** · **UI 독립 레이어** ·
  **입력 추상화**(터치/패드/KB 교체 가능) · 콘텐츠 파이프라인 · 콘텐츠 검증 자동화.

### 코어 루프
- **"한 판 더" 훅**: 시드 무작위(맵/적/드롭) + 빌드 성장(무기×스킬 시너지) + 메타 진행.
  매 판이 다르게 느껴질 이유가 있어야.

## 2. 하지 말아야 할 것 (DON'T)

1. **감상용 3D 씬(마켓플레이스 립 등)을 플레이 맵으로.** 콜리전이 사방을 막고 카메라를 가린다.
2. **캐릭터에 안 맞는 무기 억지로**(손 없는데 총 들리기).
3. **모델 하나로 플레이어/적/보스 돌려막기.** 가독성 0.
4. **구조 문제를 값 튜닝으로 덮기.** 같은 증상 2번째 손대면 멈추고 구조를 고쳐라.
5. **에셋·엔진 기본기 없이 코드부터.**
6. **juice 생략하고 "쏘면 나감/맞으면 죽음"으로 끝.**
7. **콜리전 소스 이중화**(그리드+박스 동시).
8. **배치·밝기·오클루전을 눈대중으로**(측정·자동검증 없이).
9. **갓-오브젝트 모놀리스** / **타입 없는 속성 주머니** 엔티티.
10. **시드 없는 `random` 산재** → 런 재현·리플레이·테스트 불가.
11. **UI를 게임 로직에서 직접 조작**(DOM/위젯 poke).
12. **짧은 "주기마다 뭐라도 커밋" 자동 루프.** 작은 변경만 나오고 진짜 일은 영원히 회피된다.
13. **후반 리팩터·문서·죽은코드 정리로 "진도 나가는 척".** 체감 퀄리티 0.

## 3. 조심할 것 (CAUTION — 반복해서 물린 미묘한 함정)

- **높이 = 오클루전.** 언덕/키 큰 물체를 플레이 공간에 두면 카메라가 가림. terrain 쓸 거면
  **카메라 오클루전 처리(페이드/X-ray/각도)를 세트로** 넣어라.
- **블룸 + `toneMapped:false` = 흰색 blowout.** 밝은 재질도 블룸 임계 넘으면 흰 덩어리. 클램프하라.
- **데코 씬의 harvest 콜리전**은 작은 장식까지 벽이 돼 이동을 사방에서 막는다.
- **밀도 기반 자동 봉쇄(void 막기)** 는 넓은 평지=열린 길(도로)까지 구멍낸다. 콘텐츠가 경계를
  채우면 그냥 경계 클램프로 충분.
- **스폰이 시야 밖 + aggro 사거리 밖**이면 도먼트로 안 싸운다. 플레이어 기준 스폰 + 즉시 aggro.
- **고정 코너 스폰**은 플레이어가 지나치면 전투가 안 생긴다.
- **normalize/스케일 바꾸면 앵커 좌표도 같은 배율로.** 안 하면 배치 다 어긋남.
- **첫 로드 맵 에셋이 무거우면**(수십 MB) 모바일에서 "맵 안 뜸". 첫 맵은 가볍게 / 압축.
- **인스턴스마다 geometry·material `new`** = GPU 버퍼 누수. **공유 캐시** 재사용, 미사용은 despawn.
- **데스크톱 백그라운드 탭의 렌더/RAF는 못 믿는다**(스로틀·캄캄). 위치는 코드 probe로,
  프레임 비용은 동기 루프로, 최종 시각은 실기기로.

## 4. 권장사항 (RECOMMENDATIONS)

- **엔진**: 웹 배포가 필수 아니면 **Unity/Godot/Unreal** — 지형·NavMesh·애니 블렌딩·물리·파티클·
  카메라(Cinemachine 류)·포스트 파이프라인이 전부 내장. "제대로/AAA"면 핸드롤 three.js로
  이걸 맨손 재구현하는 비용을 각오해야 함(대개 반쪽만 됨). 웹 필수면 three.js + 아래 아키텍처.
- **에셋**: 통일된 에셋팩(스토어) 또는 외주. **립 잡동사니 금지.** 팔레트·라이팅 컨셉 먼저 고정.
- **워크플로**: **수직 슬라이스** — 한 캐릭터·한 적·한 무기·한 방을 AAA 손맛까지. 그 다음에만 확장.
- **스코프**: 콘텐츠 양은 작게, **크래프트는 AAA.** 적게 만들되 극도로 polished.
- **툴**: 인게임 디버그 오버레이 + 라이브 튜닝 + 콘텐츠 검증 자동화 + 시드 리플레이.
- **측정**: perf = draw call/tris/frame ms 실측. 룩 = 팔레트/휘도. 손맛 = 플레이테스트.
- **성공 관문**: "빌드 그린"이 아니라 **"수직 슬라이스가 재밌고 좋아 보이나"**.

## 5. 코드 아키텍처 & 인터페이스 구조 (AAA-grade)

> 핵심: **시스템 경계를 그으면 "한 시스템만" 바꿀 수 있다.** 경계가 없으면 하나 건드릴 때마다
> 전부 흔들려, 결국 증상만 반복 수정하게 된다(실패 프로젝트가 이걸로 무너졌다).

### 5.1 레이어 (의존성 위→아래 한 방향)

```
App/Boot        플랫폼, 에셋 로드, 설정, 진입점
  └ Core        루프(고정 timestep sim + 가변 render), 시계, 이벤트버스, 시드 RNG, DI/서비스로케이터
      └ Systems 입력·이동·전투·무기·투사체·AI·스폰·루팅·진행·카메라·VFX·오디오·애니
          └ Data 무기/적/레벨/웨이브/드롭/스킬 = 순수 데이터(콘텐츠)
      └ Presentation  렌더 파이프라인(라이팅/그림자/톤매핑/포스트스택) — sim과 분리
      └ UI      HUD/메뉴 = 게임 이벤트 구독하는 독립 레이어 (로직이 UI를 직접 조작 X)
      └ Meta    세이브/해금/메타진행
      └ Tools   디버그 오버레이·라이브 튜닝·콘텐츠 검증
```

### 5.2 엔티티/컴포넌트 (ECS 또는 최소 컴포넌트)

갓-오브젝트 + 속성 주머니 대신 **엔티티 = id + 타입드 컴포넌트 집합**:

- 컴포넌트(데이터만): `Transform, Velocity, Health, Collider, Renderable, Animator, Weapon,
  AIBrain, Faction, StatusEffects, Lifetime`.
- 시스템(로직만): 필요한 컴포넌트를 가진 엔티티만 순회. 예 `MovementSystem`은 `Transform+
  Velocity+Collider`.
- 이점: 새 적/무기 = 컴포넌트 조합. 시스템 단위 테스트·교체. (풀 ECS가 부담이면 타입드 컴포넌트
  필드 + 시스템 함수만으로도 충분.)

### 5.3 시스템 인터페이스 — 각자 `update(dt, world)` + 좁은 API, 통신은 이벤트/스토어로

- `InputSystem` → 입력(키/마우스/패드/터치)을 **의도(intent: move/aim/fire/dash)**로 추상화.
  입력 소스 교체돼도 로직 불변.
- `MovementSystem` → 이동 + 지형추적 + 콜리전(단일 소스).
- `CameraSystem` → 추적·리드·오클루전 페이드·셰이크(서비스).
- `WeaponSystem`/`ProjectileSystem` → 발사·탄·머즐(총구 트랜스폼 하나).
- `CombatSystem`/`DamageSystem` → 피해·iframe·넉백·히트스톱(이벤트 발행).
- `AISystem` → 스티어링·상태(추격/텔레그래프/공격), 데이터 주도 행동트리.
- `SpawnDirector` → 웨이브·난이도 예산·플레이어 기준 스폰.
- `VFXSystem`/`AudioSystem` → **juice를 서비스로**: `shakeCamera(x)`, `hitstop(ms)`,
  `spawnImpact(pos)`, `playSfx(id,bus)`. 아무 시스템이나 호출.
- `AnimationSystem` → 상태머신(idle/run/fire/hit/death) + 블렌딩.

### 5.4 상태 & 이벤트 & 무작위

- **게임 상태머신**: `Boot→Menu→Loadout→Run→Pause→GameOver→Meta`. 각 상태가 enter/update/exit
  소유. 불리언 난립 금지.
- **이벤트버스**: `EnemyKilled, PlayerHit, WeaponFired, LevelUp, WaveCleared…`. UI·오디오·VFX·
  진행 시스템이 구독. 발신자는 수신자를 모름 → 결합 끊김.
- **시드 RNG**: 런 시작 시 시드 고정. 모든 무작위는 이 RNG로 → 재현·리플레이·밸런스 테스트 가능.

### 5.5 UI / 인터페이스

- **UI는 독립 레이어**: 게임 이벤트/상태 구독해 그림. 로직이 UI를 직접 조작 X.
- **입력 추상화와 대칭**: HUD가 현재 입력 스킴(터치/패드/KB)에 맞춰 프롬프트 전환.
- 레이어 분리: 월드 HUD(체력/목표/미니맵) · 피드백(데미지수/토스트/경고) · 메뉴/모달(인벤/스킬/
  상점/일시정지) · 오버레이(로딩/전환/결과). 각자 독립.
- 반응형·세이프에어리어·접근성(색맹 팔레트/텍스트 스케일) 처음부터.

### 5.6 콘텐츠 파이프라인 & 검증

- 무기/적/레벨/웨이브/드롭/스킬 = 순수 데이터. 시스템이 읽어 구동.
- **콘텐츠 검증 자동화**: 로드 시 앵커 지면/도달성/밸런스 sanity 체크 → 리그레션 차단.
- 밸런스는 데이터 편집으로. **단, 구조 문제를 데이터 튜닝으로 덮지 말 것.**

## 6. 개발 순서 & 성공 관문

1. 엔진 결정 → **리그드 캐릭터 + 무기 소켓** 확보 → **사격 한 방이 제대로**부터.
2. 이동/지형/카메라(오클루전 포함) — 기본 이동감.
3. **적 1종 + 전투 juice — "치는 맛"이 나는지가 관문.** 여기서 재미 없으면 콘텐츠 무의미.
4. 스폰 디렉터 + 텔레그래프 + 적 3종.
5. 레벨 1개(의도된 흐름) + 자동 배치검증.
6. 코어 루프(빌드/진행/시드 무작위).
7. **그다음에야** 콘텐츠 확장 + 밸런싱.

> **관문은 3번(전투 손맛의 수직 슬라이스).** 재밌으면 확장, 아니면 멈추고 손맛부터.
> 실패 프로젝트는 1~3을 건너뛰고 5~7을 튜닝하다 껍데기가 됐다.
