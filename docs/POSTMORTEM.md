## 2. 왜 퀄리티가 안 변했나 — 퀄리티를 정하는 걸 아무것도 안 함

**3D 게임 체감 퀄리티의 ~80%는 아트·손맛(모델/애니/VFX/라이팅/일관성).** 그 레이어를
219커밋 동안 **한 번도 제대로 안 건드렸다.**

- 아트 6커밋(전부 다운로드) vs 코드 90커밋. 비주얼 천장은 **"짝 안 맞는 공짜 에셋"에 처음부터
  고정**돼 있었고, 코드를 아무리 커밋해도 그 천장은 안 움직였다.
- 무기 5종은 수치만 달랐지 손맛(반동/히트스톱/파티클/사운드)이 같았다 → 전투 체감 동일.
- 캐릭터=적=보스 같은 병아리 → 난전 가독성 0.

**결론: 코드는 219번 바뀌었지만 "퀄리티를 결정하는 축(아트/손맛)"은 0번 바뀌었다.**

## 3. 왜 실패했나 — 4가지 구조적 원인

1. **증상만 반복, 근본 회피.** city 23회·밝기 10회·배치/walkable/오클루전을 계속 "고침".
   근본(데코 GLB를 플레이맵으로 씀 + 짝 안 맞는 에셋)을 안 건드리니 밴드에이드가 매번 재발.
   결국 맵을 통째로 3번 갈아엎음(포레스트→제거, 시티 GLB→아레나→방향성 레인, 보스 GLB→아레나).
2. **성공 관문을 잘못 잡음.** "빌드 그린 + 앵커가 walkable 위 + gh run watch 성공"을 성공으로 침.
   정작 관문이어야 할 **"전투가 재밌나 / 통일감 있나"** 는 한 번도 게이트로 안 씀.
3. **자율 30분 루프가 실패를 구조화.** 30분마다 "머지 가능한 뭔가"를 강제 → 그 안에 되는 건
   항상 **제일 작은 변경(튜닝/버그픽스/리팩터)**. 아트·손맛·재설계 같은 "30분에 못 끝내는 진짜
   일"을 루프가 구조적으로 회피. → 움직임 219, 퀄리티 델타 0.
4. **후반 코드-청소 도피.** 색 팔레트 추출·매직넘버→CONFIG·죽은코드 제거·문서 22개.
   플레이어 체감 퀄리티 영향 **0**인데 "진도 나가는 척" 하기 좋음.

## 4. 로직/코드 구조도 근본이 틀렸다

퀄리티뿐 아니라 아키텍처 자체가 상용 게임 구조가 아니었다. (상세·해법은
`NEXT_GAME_GUIDE.md`의 "코드 아키텍처" 절.)

- **`Game.js` 2000줄 갓-오브젝트** — 상태 + 전투 + 렌더 + 입력 + UI DOM 조작 + 스폰 + AI 글루가
  한 클래스에 전부. `this.*`로 모든 게 서로 직접 손댐 → 교체·테스트·재사용 불가.
- **엔티티 = `THREE.Group` + `userData` 잡주머니** (타입 없음, 뭐든 쑤셔넣음).
- **"데이터 주도"는 값만.** 동작은 전부 한 파일 → 시스템 경계 없음.
- **UI = DOM id를 게임 로직에서 직접 poke** → 표현과 로직 결합.
- **상태머신 없음** (started/ended/panel 불리언 조합).
- **시드 RNG 없음** (`Math.random` 산재) → 런 재현 불가, 로그라이트 기본 안 됨.
- **렌더 파이프라인 애드혹** (bloom+toneMapped 함정에 반복해서 물림).
- **맵 = 데코 GLB** (콘텐츠와 기술 혼동).
